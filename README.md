# Pitchroom — защита и оценка презентаций

Приложение для проведения защиты студенческих проектов: студенты загружают PDF,
преподаватель синхронно показывает слайды, группа оценивает работу по четырём критериям.

## Админ-панель

Админ-панель закрыта логином и паролем. По умолчанию:

| Логин | Пароль |
|-------|--------|
| `admin` | `admin` |

После входа создаётся подписанная HttpOnly-cookie на 12 часов; все страницы
`/admin/*` и создание сессий (`POST /api/groups`) без неё недоступны.
Страница входа — `/admin/login`, кнопка выхода — в правом верхнем углу панели.

Сменить логин и пароль можно переменными окружения воркера (на сервере — файл
`/etc/pitchroom.env`):

```
ADMIN_LOGIN=admin
ADMIN_PASSWORD=новый-пароль
ADMIN_SESSION_SECRET=случайная-строка
```

Учтите: пока приложение открыто по `http://`, логин и пароль передаются по сети
без шифрования. Для публичного доступа лучше поставить домен и HTTPS.

## Управление показом

На экране показа презентацию можно развернуть на весь экран, а слайды
переключать кликером (пультом), клавиатурой или кликом по слайду:

| Действие | Как |
|---|---|
| Следующий слайд | `→` `↓` `Page Down` `Пробел` `Enter` `N` или клик по слайду |
| Предыдущий слайд | `←` `↑` `Page Up` `Backspace` `P` |
| Полный экран | `F` или кнопка «⛶ Полный экран» |
| Выйти из полного экрана | `Esc` |

Слайд всегда вписывается в экран целиком, поэтому прокручивать его не нужно.
Презентация загружается один раз при старте показа, дальше слайды переключаются
мгновенно — даже если PDF большой. Рядом со номером слайда видно общее число
страниц, на последнем слайде переключение вперёд блокируется.
Студенты видят тот же слайд и тоже могут развернуть его на весь экран кнопкой
в шапке — переключает слайды только преподаватель.

## Сессии и авторы работ

Сессию можно удалить прямо из админ-панели: кнопка «Удалить» на карточке в
списке сессий или кнопка «Удалить сессию» в шапке открытой сессии. Вместе с
сессией безвозвратно удаляются все загруженные PDF, презентации и оценки, а
ссылка `/g/<код>` перестаёт открываться. Карточка удалённой сессии убирается и
из списка в браузере преподавателя.

Работу может защищать команда: при загрузке презентации студент заполняет поле
«Авторы работы» и перечисляет соавторов через запятую (по умолчанию там его
собственное ФИО). Соавторы видны преподавателю в списке презентаций, на слайдах
и в результатах, а каждый из них видит работу в разделе «Загруженные работы».
Если поле оставить пустым, автором считается загрузивший.

## Работа на сервере

Подробная инструкция по развёртыванию на любом сервере — в
[`deploy/README.md`](deploy/README.md). Там же готовые конфиги для Apache и nginx,
запуск как фоновой задачи (systemd / pm2 / tmux), HTTPS, обновление и резервные копии.

Короткий путь на чистом сервере (Ubuntu/Debian):

```bash
cd /opt/pitchroom
sudo ./deploy/install.sh
```

Скрипт поставит Node.js 22, соберёт проект, создаст `/etc/pitchroom.env`,
запустит systemd-службу `pitchroom` и проверит, что страница входа отвечает.

Управление службой:

```bash
systemctl status pitchroom          # состояние
journalctl -u pitchroom -f          # журнал
systemctl restart pitchroom         # перезапуск
```

Данные (группы, оценки и загруженные PDF) хранятся в
`/opt/pitchroom/.wrangler/state` и сохраняются при обновлениях и перезапусках.
Именно эту папку нужно забрать, чтобы сделать резервную копию.

### Обновление приложения

Из папки проекта на компьютере (сборка локально и заливка на сервер):

```bash
PITCHROOM_SSH_PASSWORD='пароль root' PITCHROOM_HOST=адрес-сервера ./deploy/deploy.sh
```

Скрипт собирает production-версию, загружает её на сервер, обновляет
systemd-службу и проверяет, что страница входа отвечает. Данные при этом не трогаются.

## Чего делать не нужно

- **Не запускайте `vinext start` / `next start` как production.** Node-сервер
  не даёт приложению биндинги D1/R2, и запросы к базе падают с 500.
  Production — это `wrangler dev` по собранному `dist/` (см. `deploy/start.sh`).
- **Не ставьте за прокси dev-сервер (`npm run dev` / `npm run lan`).**
  Apache и nginx пробрасывают заголовок `Upgrade`, а dev-сервер на нём падает
  целиком (вплоть до 502/503 до ручного перезапуска).

## Локальный запуск

Приложение можно запустить и на компьютере преподавателя — тогда студенты
подключаются по локальной сети Wi‑Fi или Ethernet.

Установите Node.js 22 или новее, откройте Терминал в папке проекта и выполните:

```bash
npm install
npm run lan
```

После запуска в терминале появятся два адреса:

- `Local` — адрес для открытия на компьютере преподавателя;
- `Network` — адрес для студентов в той же сети, например `http://192.168.1.25:3000`.

Админ-панель находится по адресу `http://<IP-компьютера>:3000/admin`. Созданные в ней короткие ссылки автоматически используют сетевой адрес, с которого была открыта панель.

Не закрывайте Терминал во время занятия. Для остановки приложения нажмите `Control + C`.

## Данные

Группы, оценки и загруженные PDF хранятся локально в служебной папке `.wrangler`. Не удаляйте её, если хотите сохранить материалы между запусками.

Если macOS впервые спросит, разрешить ли входящие подключения для Node или workerd, нажмите «Разрешить».

## Структура

- `app/` — страницы и API (App Router);
- `app/lib/auth.ts` — вход в админ-панель и cookie сессии;
- `app/lib/authors.ts` — авторы работы: нормализация списка соавторов и показ имён;
- `deploy/` — развёртывание: `README.md` (инструкция), `install.sh`, `uninstall.sh`,
  `deploy.sh`, `start.sh`, `pitchroom.service`, `apache-pitchroom.conf`,
  `nginx-pitchroom.conf`, `pitchroom.env.example`;
- `db/schema.ts` — схема базы D1.
